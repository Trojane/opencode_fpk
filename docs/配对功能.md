# Pairing（配对）：让其他设备接入 NAS 上的 OpenCode

## 它解决什么

opencode 本体只监听 `127.0.0.1:14096`，由飞牛统一网关通过 unix socket 暴露给门户页面。
桌面端、手机 App 要连过来，需要一个「其他设备可达 + 有凭据」的入口。

配对把这件事做成应用里的一个页面：**设置 → Pairing**。

## 界面

| 区域 | 作用 |
| --- | --- |
| 局域网直连 | 一键开关。开启后监听 1024-65535 端口（默认 4096），供其他设备连接 |
| 服务器地址 | `http://<NAS 局域网 IP>:<端口>`，可复制 |
| 访问令牌 | 浏览器首次进入直连端口时使用；可显示/复制 |
| 配对码 | 一次性（5 分钟）。生成后显示二维码与配对链接 |

## 三种接入方式

| 方式 | 用的凭据 | 适合 |
| --- | --- | --- |
| 扫码 / 粘贴配对链接 | 一次性配对码（`/auth/connect/<code>`） | 桌面端「添加服务器」、手机 App 扫码 |
| 地址 + 密码 | opencode serve 的服务密码（Basic） | 客户端直接填地址和密码 |
| 浏览器打开直连地址 | 访问令牌（换 cookie，30 天） | 临时用另一台电脑的浏览器 |

## 实现

后端（`src/app/server/pairing.go`）：

- `GET  /__pair/api/state` — 直连状态、端口、局域网地址、令牌、服务是否在线
- `POST /__pair/api/pair` — 带 Basic 调上游 `/api/pair`，返回 `{code, expires_in, urls, link, qr}`
  - 二维码载荷与官方一致：`{"code":"…","urls":["http://ip:port"]}`
- `POST /__pair/api/enable` — 写 `oc_home/port_tcp` 并在运行中拉起监听（无需重启）

前端（`src/app/server/pair_ui.go`，注入到 shim 尾部）：
在设置侧栏「设置」之后插入一项 **Pairing**，点击打开自绘面板（Shadow DOM 隔离样式，跟随明暗主题）。

直连端口的鉴权（`startTCP`）：

1. 令牌 cookie → 通过（门户代理，注入 Basic）
2. `/auth/connect/<code>` → 放行，由上游校验配对码
3. 带 `Authorization` 的请求 → 走不注入凭据的代理，由上游校验地址+密码

## 安全边界

- 面板本身只从门户进入，受飞牛登录态保护
- 直连端口默认关闭；关闭后端口不再接受新连接（已建立的会话不受影响）
- 配对码一次性、5 分钟有效；令牌 32 位十六进制，存 `oc_home/.access_token`（0600）
- 开启直连等于把这台 NAS 上的 OpenCode 暴露到局域网，不用时请关掉

## 验证记录

在真机（fnOS / x86_64 / opencode 2.2.5）上以独立端口跑了一份临时实例验证：

- `GET /app/opencode/__pair/api/state` → 返回端口、地址、令牌，`online:true`
- `POST /__pair/api/enable {on:true}` → 立即监听 4096，`state.enabled:true`
- `POST /__pair/api/pair` → 拿到一次性 code、配对链接与二维码（1590 字节 data URL）
- `GET :4096/auth/connect/<有效码>` → `200 {"token":"…"}`
- `GET :4096/auth/connect/<无效码>` → `401 Pairing link expired or already used`
- 浏览器实测：侧栏出现 `设置 / Pairing / 帮助`，面板开关、地址、令牌、二维码均正常
