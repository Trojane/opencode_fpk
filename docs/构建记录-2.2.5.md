## 相对 2.2.1 基线包改了什么

基线：`lin1740/fnos-OpenCode` 的 `opencode_all_2.2.1`（commit 内容见仓库根目录）。
适配层共 4 处改动，全部在 `patches/` 下：

1. **`gateway.go` — 版本常量**
   `const VERSION = "1.19.3"` → `"2.2.5"`。该值只用于 `/version` 与 JS 里的版本常量改写，不影响上游协议。

2. **`gateway.go` — 前缀路由补齐**（真 Bug，2.2.1 也存在）
   `mux` 里 `/gateway/status`、`/gateway/healthz` 只注册了不带前缀的路径。浏览器实际请求
   `/app/opencode/gateway/status`，会落到 `/` 兜底 → 转发上游 → 上游 SPA 返回 HTML → 被
   SPA guard 纠正成 404，导致页面顶部「项目文件目录」提示条永远不显示。
   改为同一 handler 同时注册 `/gateway/status` 与 `/app/opencode/gateway/status`。

3. **`shim_gen.go` — 一键打开项目适配 v2**
   旧逻辑依赖中文文案（「还没有内容」「添加项目」「我的项目」）和旧接口 `/find/file`，
   而 2.2.5 默认英文界面且 API 迁移到 `/api/*`，旧逻辑完全失效。
   改为：空态匹配 `Create a session to get started` / `Nothing here yet`（保留中文），
   点 `Add project` 后在目录弹层点 `Select folder`；仅当弹层路径含 `/projects` 或
   `opencode/var` 时才自动确认，避免干扰用户手动导航。

4. **`manifest` / `应用介绍.txt` — 元数据**
   `version=2.2.5`、`changelog` 重写、介绍文案版本号同步。

## 为什么不用改更多

`opencode serve` 的参数没变（`--hostname/--port`），默认密码仍以
`server password <pw>` 打到 stdout（实测 43 字节），网关的 `passScanWriter` 照旧能捕获并注入
Basic Auth。v2 的 API 前缀变成 `/api/*`，但网关的 `injectShim` 有 `="/"` 通配改写、
`STR_PATHS` 本身含 `/api/`，运行时 shim 又会给所有同源绝对路径补前缀，所以服务端与浏览器两侧
都自然适配，不需要逐条改路由表。

## 构建步骤（可复现）

```bash
# 0) 依赖：go >= 1.21、fnpack 1.2.3
# 1) 取 2.2.1 基线源码包（含 cmd/config/wizard/manifest/icons）
git clone --depth 1 https://github.com/lin1740/fnos-OpenCode
cp -a fnos-OpenCode/opencode_all_2.2.1 opencode && cd opencode

# 2) 放入上游 2.2.5 二进制
curl -L -o x64.tar.gz   https://github.com/anomalyco/opencode/releases/download/v2.2.5/opencode-linux-x64.tar.gz
curl -L -o arm64.tar.gz https://github.com/anomalyco/opencode/releases/download/v2.2.5/opencode-linux-arm64.tar.gz
tar -xzf x64.tar.gz   && mv opencode app/opencode-linux-x64
tar -xzf arm64.tar.gz && mv opencode app/opencode-linux-arm64

# 3) 打补丁
patch -p1 < ../patches/gateway.go.diff
patch -p1 < ../patches/shim_gen.go.diff
patch -p1 < ../patches/manifest.diff

# 4) 编译网关（纯标准库，无外部依赖）
cd app/server
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -ldflags "-s -w" -o gateway_amd64 .
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -trimpath -ldflags "-s -w" -o gateway_arm64 .
chmod 755 gateway_amd64 gateway_arm64 && cd ../..

# 5) 打包
fnpack build -d .
mv opencode.fpk opencode_all_2.2.5.fpk
```

## 已知无害现象

- 浏览器控制台有两条 404：`/app/opencode/provider`、`/app/opencode/agent`。
  这是 2.2.5 前端自带的旧路径探测（真正数据走 `/api/provider`、`/api/agent`），
  在官方原生部署下同样会 404，不影响功能。
- `cmd/install_callback` 里引用了 `server/opencode-setup_amd64|arm64`，基线包里本就没有这两个文件，
  逻辑自动跳过（`[ -f ]` 守卫），行为与 2.2.1 一致。

## 安装 / 升级

- 全新安装：应用中心 → 手动安装 → 选 `opencode_all_2.2.5.fpk`。
- 覆盖升级：直接装同 appname 的新包，`uninstall_init` 会先停网关，`upgrade_callback` 保留
  `oc_home`（API Key、会话）与 `projects`。
- 升级后若页面空白，先看 `应用文件/opencode/var/gateway.log` 与 `serve.log`；
  最常见原因是端口 14096 被残留进程占用（`ss -ltnp | grep 14096`）。
